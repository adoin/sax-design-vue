# Table 运行时验收记录（2026-09-04）

## 可复现入口与范围

在仓库根目录启动现有文档开发服务器（`pnpm dev`），然后分别执行：

```sh
pnpm audit:table reports/table-runtime-after.json

```

`TABLE_AUDIT_BASE_URL` 可指定其他本地端口。脚本使用仓库已安装的 Puppeteer；性能测试从 Vite 的 `/@fs/` 入口加载 `play/table-audit/index.html`，只挂载一张表，不加载整篇文档的其他示例。页面使用真实 `STable` 和项目样式，测试钩子不进入组件公开 API。测试页面包含类型检查。

- 基线：`f2dce79` 的组件实现，见 `table-runtime-before.json`。
- 改动后：本提交的组件实现，见 `table-runtime-after.json`。结果包含浏览器版本、时间、每次滚动后的窗口/缓存、几何偏差和 GC 后的内存值。
- 本地 Chrome headless，1100 × 800 视口，表格宽 960px，滚动视口高 360px，估算行高 44px，行 overscan 6、列 overscan 2，左右各一固定列。
- 覆盖普通数组 1000 行 × 30 列，以及按需生成 100 万行 × 10 万列的固定/动态行高模式。
- 每个场景包含初始化、30 次 160px 滚轮输入、最后一行及最后一个中心列跳转、卸载与强制 GC。动态源另检查长内容替换、横向窗口切换保留最大高度、短内容替换使高度回缩。
- 另连续创建、跳到末端、卸载百万行动态表格 5 次，验证 DOM 移除和高度索引没有逐次残留。

## 内存修复

原高度索引在创建虚拟列表时就分配 `Float64Array(count + 1)`，未启用的内部虚拟器和固定行高列表也付出这笔成本。百万行索引为 8,000,008 字节。

现在仅在第一次非零行高修正时分配。禁用时释放索引，重新启用时根据保留的测量记录重建；固定行高与测量值等于估算值的列表不分配。活跃动态表格在 `resetMeasurements()` 时仍清除已测量的增量并复用存储，避免拖动列宽时反复分配大数组。

单测检查实际 `Float64Array` 分配次数，覆盖均匀高度、非均匀高度、重置复用、禁用/重新启用、总行数缩小和估算高度变化。浏览器中的固定行高百万行场景不再出现约 8MB 的新增 backing storage；非均匀动态行高场景仍约增加 8MB，这是保留的真实成本。

`Runtime.getHeapUsage.backingStorageSize` 包含 ArrayBuffer 和外部字符串，不是进程 RSS，也不只代表表格。报告同时记录 JS heap 和 embedder heap；GC 会回收前一场景的临时对象，因此个别前后差值为负。不能用一次 heap 差值宣称零泄漏或推导最大可用行数。

## 窗口与缓存

| 场景 | 连续滚动最多挂载行数 | 末端挂载行数 | 末端已访问行高缓存 | 末端元素 / ref 回调 |
| --- | ---: | ---: | ---: | ---: |
| 普通数组，动态行高 | 22 | 15 | 139（普通缓存） | 15 / 15 |
| 百万行生成源，固定行高 | 22 | 15 | 0 | 0 / 0 |
| 百万行生成源，动态行高 | 20 | 12 | 108（生成源缓存） | 12 / 12 |

生成源原生轨道保持 8,000,000px；最后一行 999999、中心列 99998 及两侧固定列都可到达。各次采样的单元格顶部与所在行顶部、高度偏差均为 0。

长内容末行从 64px 增至 1058px，横向切换后仍为 1058px，替换为短内容后恢复 64px。这区分了同一布局保留最大高度和内容替换后的缓存失效。

行高历史缓存随访问过的稳定行键增长，不能称为仅占用窗口大小。测量元素和 ref 回调随挂载窗口清理；生成源没有创建完整行列矩阵。5 次卸载后的 backing storage 保持相同，JS heap 有开发运行时波动；这证明本次有限循环没有累积高度数组，不等于无限运行的泄漏证明。

## 时间结果的解释

初始化及跳转时间是浏览器 `performance.now()` 测得的组件操作到 Vue 更新和 3 个动画帧完成的时间；滚轮样本还包括 Puppeteer 输入往返。它们不是单帧 CPU 耗时，也不能换算为 FPS。原始 JSON 保留每个样本，便于同环境复测。

本次初始化约 67–150ms，末端跳转约 62–80ms；优化的结论是避免不必要的高度数组分配，不据这些少量开发模式样本宣称渲染速度提升。生产构建、不同设备、长时间运行及触屏拖动不在本轮性能测量范围内。

## 功能边界和仍需验收的组合

- 生成源由业务提供排序、筛选后的索引数据，组件不为其执行全量本地排序/筛选；全选入口不枚举生成源。
- 生成源行分组要求 `mode: remote` 的分组元数据，不能直接使用全量本地分组推断。普通树形/懒加载验证不能推导出生成源自动展开任意树数据的能力。
- 生成源修改/行重排依赖配置的业务 `apply` 等适配接口；校验、查找、剪贴板、聚合、图表有各自的范围和预算。当前运行时基准没有同时开启这些重操作，也没有为其认证百万行容量。
- 合并、详情、分组、编辑、区域选择、请求代理等已有各自回归；全部功能组合的系统性覆盖、模块边界及默认行为审核仍须按 `todos.md` 完成。
