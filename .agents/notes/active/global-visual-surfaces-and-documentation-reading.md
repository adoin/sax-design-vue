# 全局视觉层次与文档阅读节奏

## 用户要求

> “在已经有shadow的卡片中可使用 凹陷shadow来做强调”

> 需要合理分段，还有用 gap+shadow 来把一些需要强调的部分框起来。

## 视觉契约

- 项目默认采用无装饰性边框的表面。用间距、背景与阴影建立层次，不以描边包围普通容器。
- 外层卡片已有阴影时，内部需要强调的提示、限制和重要说明使用凹陷阴影，并留出与卡片正文、示例区的间距。不要只改变背景颜色，也不要嵌套多层凸起卡片。
- 同一类文档提示使用共享容器样式；tip、warning、danger 保留语义色，采用一致的圆角、内阴影、间距。
- 组件自身明确提供的 border 变体、分隔符、图表线条和功能性示例不受文档容器去边框规则影响。

## 文档阅读契约

- 说明按概念、配置、交互、范围和限制分段。一个段落围绕一个可理解的主题，复杂流程使用列表。
- 优先改善 Table 的长说明，保留行为限制、API 名称、章节顺序、英文锚点和完整示例源码。
- 重要能力差异、处理范围和限制使用带留白与内阴影的共享提示容器。避免把全部正文都包装成提示。
- 中文和英文对应调整；不得在公开文档写入工作过程或用户纠错历史。
- 本次主题与文案调整限定在文档中，不修改发布的组件实现或再次发布 npm 版本。

## 验收

- 文档示例检查、完整双语言构建通过。
- 浏览器确认提示的四边无边框，内阴影可见，提示和正文留白一致；Table 分段及强调块可读。
- 官网与 GitHub Pages 部署并核对最终页面。
